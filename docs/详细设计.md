## 3 ENGINE 设计说明

### 3.1 程序描述

ENGINE 是对外壳，重新导出类型、构造函数和错误。它只引用 `internal/application/des` 和 `internal/application/devs`。事件循环、时钟、事件队列、慢事件记录和互斥锁在下层 `internal/kernel`。两个应用互不引用，都调用这一层。下面各节描述的是这套实现的行为。

### 3.2 功能

- 创建引擎并校验选项。
- 启动、停止、等待结束。
- 按绝对仿真时间插入事件。
- 接受事件和延迟，在未来的仿真时刻触发该事件。
- 按标识取消尚未执行的事件。
- 按 1ms 桶推进，支持真实时间等待和追赶。
- 记录慢事件并提供快照。

### 3.3 性能

- 步长和慢事件阈值固定为 1ms。
- 插入未来桶的复杂度为桶内追加，外加堆操作 `O(log n)`，`n` 为非空桶数量。
- 事件处理函数执行期间不持有引擎锁。
- 日志入队为非阻塞操作，不计入处理函数耗时。

### 3.4 输入项

| --- | --- | --- |

| 事件 | 调用方或处理函数 | 名称与处理函数。绝对插入另给仿真时间；未来插入另给延迟 |

### 3.6 算法

时间：

```text
type Time int64          // 毫秒
桶下标 = 时间戳
target(k) = origin + k * 1ms
```

`Now()`：

- 正在执行某一毫秒时，返回该毫秒。
- 该毫秒已排空且下一毫秒尚未开始时，返回水位。
- `Start` 之前返回 0。

插入在引擎锁内完成：

1. 状态为停止中或已停止：返回 `ErrClosed`。
2. 名称为空：返回 `ErrName`。处理函数为空：返回 `ErrHandler`。
3. 时间戳小于 0，或小于水位：拒绝计数加一，返回 `ErrPast`。
4. 分配事件标识和插入序号。
5. `executing >= 0` 且时间戳等于 `executing`：追加到 `stepPending` 尾部。
6. 其他合法时间：放入未来桶尾部。
7. 插入计数加一，广播条件变量。

未来事件 `AddFuture(after, event)` 也在这把锁内决定触发时刻，然后执行上述步骤：

```text
after < 0           返回 ErrPast
after == 0          触发时刻 = Now()
after > 0           毫秒数 = 向上取整(after / 1ms)
                    触发时刻 = Now() + 毫秒数
```

因此 1.1ms 落在 2ms 之后的桶上，不会早于调用方给出的延迟。触发时刻等于正在执行的毫秒时，事件进入 `stepPending` 尾部。触发时刻更晚时，事件进入未来桶。调用立即返回事件标识。引擎推进到该桶时才调用处理函数。

真实模式按该桶的理论墙钟时刻等待。没有滞后时，这个时刻等于收下事件时的墙钟加上取整后的延迟。追赶期间仿真时间快于墙钟，事件仍在该仿真毫秒触发。若引擎正停在更晚的桶上等待，新的更早未来事件会打断等待。

取消只把事件标记为已取消，不从队列中间删除。弹出时发现标记则跳过处理函数，取消计数加一。未知、已执行或已取消的标识返回 `false`。

同一未来桶内的时间戳相同，桶内顺序就是插入序号。

### 3.7 流程逻辑

状态：`created` → `running` → `stopping` → `stopped`。

```text
Start
  若已启动：返回 ErrStarted
  状态改为 running
  启动循环协程
  立即返回

循环（持有引擎锁）
  若已请求停止：进入 stopping 并退出循环
  若 stepPending 为空：
      若 executing >= 0：
          watermark = executing + 1
          executing = -1
      next = 未来桶中不小于 watermark 的最小桶
      若没有 next：
          若开启空闲退出：进入 stopping 并退出循环
          否则条件等待后继续
      若 next 大于时间上限：进入 stopping 并退出循环
      若真实模式开启：
          若现在早于 target(next)：
              注册到期广播
              条件等待
              取消定时器
              继续          // 重新选择桶
          若现在晚于 target(next)：
              记录滞后，追赶次数加一
              解锁，调用滞后回调，异步写 Warn
              加锁
              若已请求停止：继续
      executing = next
      watermark = next
      stepPending = 拿走桶 next
      继续
  弹出 stepPending 队头
  若已取消：取消计数加一，继续
  解锁
  记录开始时刻
  调用处理函数；panic 被恢复为错误
  计算墙钟耗时
  若耗时大于 1ms：写入慢事件环，异步写 Warn
  若处理失败：异步写 Error，保存循环错误
  加锁
  已处理计数加一
  若处理失败：进入 stopping 并退出循环

循环结束后
  唤醒等待者
  异步写停止日志
  排空日志，最长 2 秒
  状态改为 stopped
```

开始执行桶 `next` 时，水位设为 `next`。旧水位和 `next` 之间的空毫秒由此关闭。等待期间这些毫秒仍可插入；一旦开始执行 `next`，更早的毫秒返回 `ErrPast`。

`now == target` 时不睡眠，也不记滞后。只有 `now > target` 才追赶。被跳过的空桶不逐个回调。

处理函数返回前插入的同桶事件仍能进入 `stepPending`。水位要等队列再次变空才前移。

`Pause` 在当前毫秒队列排空、水位前移之后停住，不打开下一毫秒。暂停期间可以继续插入和取消。`Resume` 继续执行。真实模式把 `origin` 增加这段暂停的墙钟时间，避免把暂停间隔当成滞后追赶。

`Checkpoint` 只在暂停态复制水位、计数、慢事件、随机源状态、起点和尚未执行的事件。已经取消的事件不写入，其取消次数记入检查点，恢复后不再计一次。事件保存名称和 `Payload`，不保存函数。`Restore` 要求这些名称已经 `Handle` 登记，然后进入暂停态。直接 `Resume` 不读取检查点。

滞后回调返回后重新检查停止信号。处理函数和滞后回调运行在循环协程上，不能调用 `Stop`、`Wait`、`Pause`、`Resume` 或 `Checkpoint`。

生产环境使用 `time.Now` 与 `time.AfterFunc`。定时器回调只负责加锁、广播和解锁。测试通过手动时钟推进时间并广播。关闭真实模式时，循环不读取墙钟，滞后为 0，滞后回调不执行。

### 3.11 限制条件

| 错误 | 条件 |
| --- | --- |
| `ErrName` | 名称为空 |
| `ErrHandler` | 处理函数为 nil |
| `ErrPast` | 时间戳为负，延迟为负，或桶小于水位 |
| `ErrClosed` | 停止中或已停止后插入 |
| `ErrStarted` | 重复启动，或对已离开初始状态的引擎恢复检查点 |
| `ErrNotRunning` | 未运行时暂停 |
| `ErrNotPaused` | 未暂停时恢复，或未暂停时取检查点 |
| `ErrHandlerName` | 检查点中的事件名称没有登记 |
| `ErrCheckpoint` | 检查点字节无法识别 |

处理函数返回错误或发生 panic 时，引擎停止，`Wait` 返回该错误。panic 不使进程退出。

其他限制：

- 处理函数和滞后回调不能做 IO，也不能调用 `Stop`、`Wait`、`Pause`、`Resume` 或 `Checkpoint`。
- 多协程插入的先后由获锁顺序决定。
- 只有处理函数内部插入时，相同种子下的随机数序列可复现。

## 4 BUCKET 设计说明

### 4.1 程序描述

BUCKET 保存尚未开始执行的未来桶。它不感知真实时间、日志和引擎状态。

### 4.2 功能

- 按毫秒追加事件。
- 查找不小于指定水位的最小非空桶。
- 拿走指定桶的全部事件。

### 4.3 性能

非空桶下标放在最小堆中。查找和插入下标为 `O(log n)`。允许堆中残留已取空的懒删除项，弹出时跳过。

### 4.4 输入项

| 输入 | 说明 |
| --- | --- |
| 桶下标 | 事件的毫秒时间戳 |
| 事件节点 | 由 ENGINE 分配 |
| 水位 | `Next` 的下界 |

### 4.5 输出项

| 输出 | 说明 |
| --- | --- |
| 下一个桶下标 | 不存在时返回失败 |
| 事件切片 | `Take` 之后该桶从映射中消失 |

### 4.6 算法

```text
Push(step, event)
    追加到 map[step] 的尾部
    若该桶刚被创建，把 step 压入最小堆

Next(minStep)
    跳过映射中已不存在的堆项
    小于 minStep 且仍然有事件的桶留在堆中
    返回第一个 >= minStep 的下标

Take(step)
    取出 map[step]
    删除 map[step]
```

### 4.7 流程逻辑

BUCKET 没有独立循环。ENGINE 在第 3.7 节的循环中调用它。

### 4.8 接口

```go
type Buckets[T any] struct { /* ... */ }

func (b *Buckets[T]) Push(step int64, ev T)
func (b *Buckets[T]) Next(minStep int64) (step int64, ok bool)
func (b *Buckets[T]) Take(step int64) []T
func (b *Buckets[T]) Len() int
```

`T` 是 ENGINE 的未导出调度节点。BUCKET 不解释处理函数，因此用泛型，避免依赖 `engine`。

### 4.9 存储分配

- `map[int64][]T`：桶内切片按插入顺序增长。
- 最小堆：保存桶下标。

无独立锁，无堆外内存。

### 4.10 注释设计

导出符号仅供 ENGINE 使用。注释说明调用方必须持有引擎锁。

### 4.11 限制条件

不接受空事件。不检查时间是否过期，过期由 ENGINE 在调用前拒绝。

### 4.12 测试计划

| --- | --- |

| B2 | `Next` 跳过小于下界的桶和已经取空的堆项 |

## 5 ASYNCLOG 设计说明

### 5.1 程序描述

ASYNCLOG 把 `slog.Handler` 包成非阻塞队列。ENGINE 持有一个实例。

### 5.2 功能

- 级别不够的记录不入队。
- 级别足够的记录克隆后非阻塞入队。
- 后台协程调用底层 handler 写出。
- 关闭时排空队列，并限制等待时间。

### 5.3 性能

- 通道容量 4096。
- `Handle` 在通道已满时立即返回，不等待写出。
- 底层 IO 只发生在后台协程，以及关闭时的排空阶段。

### 5.4 输入项

| 输入 | 说明 |
| --- | --- |
| 底层 handler | 最终写出目标。未指定时使用 `slog.Default()` 的 handler |
| 日志记录 | `slog.Record` |

### 5.5 输出项

| 输出 | 说明 |
| --- | --- |
| 写出结果 | 由底层 handler 完成 |
| 丢弃计数 | 通道满或排空超时 |

### 5.6 算法

```text
Enabled
    转给底层 handler

Handle
    若级别不够：返回
    克隆记录
    若通道可发送：入队
    否则：丢弃计数加一
    返回 nil

后台协程
    取出记录并调用底层 Handle

Close
    关闭通道
    等待后台协程，最长 2 秒
    超时未写出的记录计入丢弃数
```

`WithAttrs` 和 `WithGroup` 作用在底层 handler 上，再包回新的异步 handler。属性在入队前写入记录。

### 5.7 流程逻辑

ENGINE 的 `Stop` 先停止事件循环，再调用 `Close`。排空阶段允许 IO，因为事件循环已经退出。快照中的日志丢弃数来自这个实例。

### 5.8 接口

```go
func New(sink slog.Handler) *Logger
func (l *Logger) Handler() slog.Handler
func (l *Logger) Dropped() uint64
func (l *Logger) Close() 
```

`Close` 内部使用 2 秒时限，不接受外部超时参数。

### 5.9 存储分配

一条带缓冲通道、一个丢弃计数、一个后台协程。记录在入队前克隆，避免调用方复用记录内存。

### 5.10 注释设计

说明 `Handle` 不返回队列已满错误，避免调用方在事件循环里处理 IO 失败。

### 5.11 限制条件

- 底层 handler 的 `Enabled` 不能执行 IO。
- `Close` 只能调用一次。
- 队列满时丢弃新记录，不丢弃已入队记录。

### 5.12 测试计划

| 编号 | 内容 |
| --- | --- |
| A1 | 通道有空间时，`Handle` 在底层写出之前返回 |
| A2 | 通道满时，`Handle` 立即返回且丢弃计数增加 |
| A3 | `Close` 后，已入队记录出现在底层 handler 中 |
| A4 | 级别不够的记录不入队 |

## 7 EXAMPLE 设计说明

### 7.1 程序描述

`example/` 下每个子目录是一个可执行程序，不是库 API。队列、取消和时间上限的状态都写在示例自己的处理函数里，不进入 `engine`。

### 7.2 功能

| 程序 | 目录 | 演示的引擎能力 |
| --- | --- | --- |
| EXAMPLE | `example/realtime/` | 墙钟对齐、同毫秒追加、按延迟触发、慢事件、指标 HTTP |
| QUEUE | `example/queue/` | 因果顺序、同一毫秒接续、取消、过期拒绝、时间上限 |
| CHECKPOINT | `example/checkpoint/` | 暂停后直接恢复；检查点交给另一台引擎，按名称和 `Payload` 接回 |
| LAG | `example/lag/` | 墙钟已过的桶追赶并交出滞后，未到的桶继续等待 |
| LINE | `example/line/` | 三个原子模型用端口连接。处理时间由包裹决定，完成和开始落在同一毫秒 |
| BENCH | `example/bench/` | 关闭真实模式后的吞吐，结果写入 README。`-clock` 从 1000 条打包线起，每秒增加 1000 条，最多 5 分钟，直到偏差比值达到 10%。每条线做查商品、扣库存和记出货，并按扫描、打包、下一单间隔等待。`-robust` 在个别处理函数远超 1ms 时看比值是否冲高后落回，并核对等待事件没有漏掉 |

### 7.3 性能

QUEUE、CHECKPOINT、LAG 和 EXAMPLE 的事件数量都很少。故意变慢的处理函数只在 EXAMPLE 中保留一个。BENCH 的测量窗口见该程序的 `-duration`。

### 7.4 输入项

EXAMPLE、QUEUE、CHECKPOINT、LAG、LINE 没有命令行参数。BENCH 接受 `-duration`。`-clock` 从 1000 条打包线起，每秒增加 1000 条，最多 5 分钟，比值达到 10% 停止。`-robust` 测量超长处理之后偏差能否落回。

### 7.5 输出项

QUEUE、CHECKPOINT、LAG、LINE 把时间线写到标准输出。处理函数只把结果留在内存或通道里，打印发生在引擎协程之外。EXAMPLE 在停止后读取 `Snapshot`。

### 7.6 算法

无独立算法。LINE 使用 `engine.Coordinator`，其余示例调用 `engine` 的公开接口。

### 7.7 流程逻辑

EXAMPLE：创建引擎，启动引擎，插入事件，等到中断信号后停止，再读取快照。

QUEUE：关闭真实模式。按绝对时间排入到达事件，服务结束时再排入下一个开始。启动前取消一个到达事件。时间上限之后的桶不执行。

CHECKPOINT：先暂停再直接恢复，使暂停期间插入的事件继续执行。再次暂停后取出检查点并停止。另一台引擎登记同名处理函数，`Restore` 后仍为暂停，`Resume` 执行剩余事件。

LAG：把墙钟起点设在过去。已经错过的桶立即执行并记录滞后。更晚的桶等到理论时刻。

LINE：关闭真实模式。到货、扫描、打包各自计算下一次到点。扫描完成的同一毫秒把包裹送进打包台。

BENCH 的 `-clock`：真实模式。每条打包线在到货时按名称查商品并扣库存，扫描和打包只更新这单状态。小包和文件的扫描、打包各等 2ms，大包和易碎的扫描等 4ms、打包等 3ms，打包完成后再等 5ms 才到下一单。这些等待用 `AddFuture` 表达，处理函数里不做空转。同一批新线按毫秒错开第一次到货。

### 7.8 接口

每个程序只有 `func main()`。

### 7.9 存储分配

无独立于引擎的持久存储。QUEUE 的等待队列保存在示例自己的结构里。CHECKPOINT 的字节只留在调用方变量中。BENCH 的打包线把商品目录、库存和最近出货留在自己的结构里，库存只在事件循环里改。

### 7.10 注释设计

示例注释说明该程序演示什么，以及如何运行。

### 7.11 限制条件

示例不使用测试时钟。慢事件的真实睡眠只出现在 EXAMPLE。处理函数不做日志、网络和磁盘 IO。

### 7.12 测试计划

打包线的扣库存、大小包等待和补货由 `example/bench` 的测试覆盖。QUEUE、CHECKPOINT、LAG、EXAMPLE 的时间线不纳入自动化单测。手工运行 QUEUE 和 CHECKPOINT，时间线与第 7.7 节一致。手工运行 LAG，错过的桶不按被跳过的毫秒逐个睡眠。手工运行 EXAMPLE，标准输出出现同毫秒的两条记录，停止后打印快照。

### 7.13 尚未解决的问题

无。

## 9 协调器设计说明

### 9.1 程序描述

协调器是可选聚合，对外类型是 `engine.Coordinator`，实现在 `internal/application/devs`。`atomic.go` 定义原子模型契约，`coordinator.go` 持有根调度和检查点，`coupling.go` 持有一层组件和端口。它把原子模型的输出接到其他模型的输入，并向内核插入最近的一个到点事件。服务时间和排队仍在调用方的模型里。不使用 `Coordinator` 时，事件循环不经过接线。

### 9.2 功能

- 登记原子模型，或嵌套一层耦合模型。
- 连接输入端口、输出端口和兄弟端口。
- 模型自己计算下一次到点。负延迟按立即到点处理。不到点则等待输入。
- 到点时先取输出，再改内部状态，然后按接线转发。
- 同一毫秒有多块到点时，调用该层的选择函数。未提供时按登记顺序。
- 外部输入只排队，模型函数仍在事件循环上执行。
- 根协调器在引擎暂停后导出检查点。模型必须能导出状态，否则整次失败。

### 9.3 性能

不创建协调器时，事件循环不进入接线。创建协调器后，事件循环仍是一个协程。一次转发至少产生一次引擎事件。剩余时间变化时取消旧到点并重排。选择函数在引擎锁外执行。

### 9.4 输入项

原子模型的四个方法，端口接线，以及可选的选择函数和根输出回调。跨进程恢复时还有检查点字节。

### 9.5 输出项

离开根协调器的消息。`Snapshot` 在引擎快照上填入 `Coupled`。

### 9.6 算法

每个原子缓存下一次到点，等于上次状态变化的仿真时间加上向上取整后的等待毫秒。协调器只保留全树中最早的一个引擎事件。事件执行时先消化排队的外部输入，再执行一个最早到点的原子。转发若使另一块在当前毫秒到点，用 `AddFuture(0)` 接到当前毫秒尾部。

### 9.7 流程逻辑

```text
登记模型并接线
向引擎插入最早到点
到点
  处理排队输入
  选择一个到点原子
  取输出，执行内部变化
  沿接线把输出变成输入
  重新计算最早到点
```

### 9.8 接口

```go
type Atomic interface {
    Advance() (after time.Duration, ok bool)
    Output() []Message
    Internal()
    External(elapsed time.Duration, msg Message)
}

func NewCoordinator(eng *Engine, opts ...CoordinatorOption) (*Coordinator, error)
func (c *Coordinator) Add(name string, m Atomic) error
func (c *Coordinator) Group(name string, opts ...CoordinatorOption) (*Coordinator, error)
func (c *Coordinator) In(port, child, childPort string) error
func (c *Coordinator) Out(child, childPort, port string) error
func (c *Coordinator) Link(from, fromPort, to, toPort string) error
func (c *Coordinator) Inject(port string, payload []byte) error
func (c *Coordinator) Snapshot() Snapshot
func (c *Coordinator) Checkpoint() ([]byte, error)
func (c *Coordinator) Restore(ctx context.Context, data []byte) error
```

`WithSelect` 只影响当前这一层。`WithOutput` 和 `WithEventName` 只对根协调器有效。默认事件名是 `coordinator`。

### 9.9 存储分配

接线表和到点缓存位于协调器。模型状态位于调用方的原子模型。检查点同时保存引擎字节、每个原子导出的状态，以及距上次变化的仿真时间。

### 9.10 注释设计

对外 API 使用英文 godoc。

### 9.11 限制条件

模型函数和根输出回调运行在事件循环上，不能做 IO，不能调用 `Stop`、`Wait`、`Pause`、`Resume`、`Checkpoint`，也不能回调协调器。名称不能包含 `/`。嵌套协调器不能 `Inject`、`Checkpoint` 或 `Restore`。同一进程暂停后直接恢复不读取检查点。

### 9.12 测试计划

| 编号 | 内容 |
| --- | --- |
| D1 | 输出沿接线到达下一模型，零延迟落在同一毫秒 |
| D2 | 1.5ms 向上取整为 2ms |
| D3 | 同一毫秒多块到点时按选择函数执行 |
