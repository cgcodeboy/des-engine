## 3 ENGINE 设计说明

### 3.1 程序描述

ENGINE 是仿真内核。它持有时钟、事件队列、慢事件记录和一把互斥锁，并在单独协程上按毫秒桶执行处理函数。

### 3.2 功能

- 创建引擎并校验选项。
- 启动、停止、等待结束。
- 按绝对仿真时间插入事件。
- 接受事件和延迟，在未来的仿真时刻触发该事件。
- 按标识取消尚未执行的事件。
- 按 1ms 桶推进，支持真实时间等待和追赶。
- 记录慢事件并提供快照。

### 3.3 性能

- 步长和慢事件阈值固定为 1ms。
- 插入未来桶的复杂度为桶内追加，外加堆操作 `O(log n)`，`n` 为非空桶数量。
- 事件处理函数执行期间不持有引擎锁。
- 日志入队为非阻塞操作，不计入处理函数耗时。

### 3.4 输入项

| 输入 | 来源 | 说明 |
| --- | --- | --- |
| 选项 | 调用方 | 真实模式、起点、滞后回调、日志目标、种子、空闲退出、时间上限 |
| 事件 | 调用方或处理函数 | 名称与处理函数。绝对插入另给仿真时间；未来插入另给延迟 |
| 取消标识 | 调用方或处理函数 | 已分配的事件标识 |

### 3.6 算法

时间：

```text
type Time int64          // 毫秒
桶下标 = 时间戳
target(k) = origin + k * 1ms
```

`Now()`：

- 正在执行某一毫秒时，返回该毫秒。
- 该毫秒已排空且下一毫秒尚未开始时，返回水位。
- `Start` 之前返回 0。

插入在引擎锁内完成：

1. 状态为停止中或已停止：返回 `ErrClosed`。
2. 名称为空：返回 `ErrName`。处理函数为空：返回 `ErrHandler`。
3. 时间戳小于 0，或小于水位：拒绝计数加一，返回 `ErrPast`。
4. 分配事件标识和插入序号。
5. `executing >= 0` 且时间戳等于 `executing`：追加到 `stepPending` 尾部。
6. 其他合法时间：放入未来桶尾部。
7. 插入计数加一，广播条件变量。

未来事件 `AddFuture(after, event)` 也在这把锁内决定触发时刻，然后执行上述步骤：

```text
after < 0           返回 ErrPast
after == 0          触发时刻 = Now()
after > 0           毫秒数 = 向上取整(after / 1ms)
                    触发时刻 = Now() + 毫秒数
```

因此 1.1ms 落在 2ms 之后的桶上，不会早于调用方给出的延迟。触发时刻等于正在执行的毫秒时，事件进入 `stepPending` 尾部。触发时刻更晚时，事件进入未来桶。调用立即返回事件标识。引擎推进到该桶时才调用处理函数。

真实模式按该桶的理论墙钟时刻等待。没有滞后时，这个时刻等于收下事件时的墙钟加上取整后的延迟。追赶期间仿真时间快于墙钟，事件仍在该仿真毫秒触发。若引擎正停在更晚的桶上等待，新的更早未来事件会打断等待。

取消只把事件标记为已取消，不从队列中间删除。弹出时发现标记则跳过处理函数，取消计数加一。未知、已执行或已取消的标识返回 `false`。

同一未来桶内的时间戳相同，桶内顺序就是插入序号。

### 3.7 流程逻辑

状态：`created` → `running` → `stopping` → `stopped`。

```text
Start
  若已启动：返回 ErrStarted
  状态改为 running
  启动循环协程
  立即返回

循环（持有引擎锁）
  若已请求停止：进入 stopping 并退出循环
  若 stepPending 为空：
      若 executing >= 0：
          watermark = executing + 1
          executing = -1
      next = 未来桶中不小于 watermark 的最小桶
      若没有 next：
          若开启空闲退出：进入 stopping 并退出循环
          否则条件等待后继续
      若 next 大于时间上限：进入 stopping 并退出循环
      若真实模式开启：
          若现在早于 target(next)：
              注册到期广播
              条件等待
              取消定时器
              继续          // 重新选择桶
          若现在晚于 target(next)：
              记录滞后，追赶次数加一
              解锁，调用滞后回调，异步写 Warn
              加锁
              若已请求停止：继续
      executing = next
      watermark = next
      stepPending = 拿走桶 next
      继续
  弹出 stepPending 队头
  若已取消：取消计数加一，继续
  解锁
  记录开始时刻
  调用处理函数；panic 被恢复为错误
  计算墙钟耗时
  若耗时大于 1ms：写入慢事件环，异步写 Warn
  若处理失败：异步写 Error，保存循环错误
  加锁
  已处理计数加一
  若处理失败：进入 stopping 并退出循环

循环结束后
  唤醒等待者
  异步写停止日志
  排空日志，最长 2 秒
  状态改为 stopped
```

开始执行桶 `next` 时，水位设为 `next`。旧水位和 `next` 之间的空毫秒由此关闭。等待期间这些毫秒仍可插入；一旦开始执行 `next`，更早的毫秒返回 `ErrPast`。

`now == target` 时不睡眠，也不记滞后。只有 `now > target` 才追赶。被跳过的空桶不逐个回调。

处理函数返回前插入的同桶事件仍能进入 `stepPending`。水位要等队列再次变空才前移。

滞后回调返回后重新检查停止信号。处理函数和滞后回调运行在循环协程上，不能调用 `Stop` 或 `Wait`。

生产环境使用 `time.Now` 与 `time.AfterFunc`。定时器回调只负责加锁、广播和解锁。测试通过手动时钟推进时间并广播。关闭真实模式时，循环不读取墙钟，滞后为 0，滞后回调不执行。

### 3.8 接口

```go
type Time int64
type ID uint64
type Handler func(Context) error

func New(opts ...Option) (*Engine, error)
```

`WithHorizon(until)` 生效时，不执行时间戳大于 `until` 的桶。时间戳等于 `until` 的桶仍执行。

### 3.9 存储分配

引擎锁保护以下数据：

| 字段 | 类型职责 |
| --- | --- |
| `state` | `created`、`running`、`stopping`、`stopped` |
| `watermark` | 已关闭毫秒上界 |
| `executing` | 正在执行的毫秒，空闲时为 `-1` |
| `stepPending` | 当前步长队列，头出尾进 |
| `buckets` | BUCKET 的未来桶 |
| `eventsByID` | 尚未执行事件的取消标记 |
| `origin`、`realtime`、`horizon`、`exitWhenIdle` | 运行参数 |
| `rand` | 种子默认 1 的随机数发生器 |
| `slowRing` | 容量 128 的慢事件环 |
| 计数器 | 已插入、已执行、已取消、已拒绝、处理错误、追赶次数、慢事件总数 |
| `lastLag` | 最近一次滞后 |
| `loopErr` | `Wait` 返回的错误 |

慢事件环在锁内更新。对应 Warn 在解锁之后入队。环满时丢弃最旧记录，`slow_total` 继续增加。

```go
type SlowEvent struct {
    ID       ID
    Name     string
    At       Time
    Step     int64
    Elapsed  time.Duration
    Overrun  time.Duration
    Finished time.Time
}
```

`Overrun = Elapsed - time.Millisecond`。`Elapsed` 只包含处理函数调用，不包含入队、锁等待和桶调度。

### 3.10 注释设计

对外 API 使用英文 godoc。设计文档使用中文。不在代码中重复本文已说明的流程。

### 3.11 限制条件

| 错误 | 条件 |
| --- | --- |
| `ErrName` | 名称为空 |
| `ErrHandler` | 处理函数为 nil |
| `ErrPast` | 时间戳为负，延迟为负，或桶小于水位 |
| `ErrClosed` | 停止中或已停止后插入 |
| `ErrStarted` | 重复启动 |

处理函数返回错误或发生 panic 时，引擎停止，`Wait` 返回该错误。panic 不使进程退出。

其他限制：

- 处理函数和滞后回调不能做 IO，也不能调用 `Stop`、`Wait`。
- 多协程插入的先后由获锁顺序决定。
- 只有处理函数内部插入时，相同种子下的随机数序列可复现。

## 4 BUCKET 设计说明

### 4.1 程序描述

BUCKET 保存尚未开始执行的未来桶。它不感知真实时间、日志和引擎状态。

### 4.2 功能

- 按毫秒追加事件。
- 查找不小于指定水位的最小非空桶。
- 拿走指定桶的全部事件。

### 4.3 性能

非空桶下标放在最小堆中。查找和插入下标为 `O(log n)`。允许堆中残留已取空的懒删除项，弹出时跳过。

### 4.4 输入项

| 输入 | 说明 |
| --- | --- |
| 桶下标 | 事件的毫秒时间戳 |
| 事件节点 | 由 ENGINE 分配 |
| 水位 | `Next` 的下界 |

### 4.5 输出项

| 输出 | 说明 |
| --- | --- |
| 下一个桶下标 | 不存在时返回失败 |
| 事件切片 | `Take` 之后该桶从映射中消失 |

### 4.6 算法

```text
Push(step, event)
    追加到 map[step] 的尾部
    若该桶刚被创建，把 step 压入最小堆

Next(minStep)
    跳过映射中已不存在的堆项
    小于 minStep 且仍然有事件的桶留在堆中
    返回第一个 >= minStep 的下标

Take(step)
    取出 map[step]
    删除 map[step]
```

### 4.7 流程逻辑

BUCKET 没有独立循环。ENGINE 在第 3.7 节的循环中调用它。

### 4.8 接口

```go
type Buckets[T any] struct { /* ... */ }

func (b *Buckets[T]) Push(step int64, ev T)
func (b *Buckets[T]) Next(minStep int64) (step int64, ok bool)
func (b *Buckets[T]) Take(step int64) []T
func (b *Buckets[T]) Len() int
```

`T` 是 ENGINE 的未导出调度节点。BUCKET 不解释处理函数，因此用泛型，避免依赖 `engine`。

### 4.9 存储分配

- `map[int64][]T`：桶内切片按插入顺序增长。
- 最小堆：保存桶下标。

无独立锁，无堆外内存。

### 4.10 注释设计

导出符号仅供 ENGINE 使用。注释说明调用方必须持有引擎锁。

### 4.11 限制条件

不接受空事件。不检查时间是否过期，过期由 ENGINE 在调用前拒绝。

### 4.12 测试计划

| 编号 | 内容 |
| --- | --- |
| B1 | 同一桶按追加顺序取出 |
| B2 | `Next` 跳过小于下界的桶和已经取空的堆项 |
| B3 | `Take` 后该桶不再被 `Next` 返回 |

### 4.13 尚未解决的问题

无。

## 5 ASYNCLOG 设计说明

### 5.1 程序描述

ASYNCLOG 把 `slog.Handler` 包成非阻塞队列。ENGINE 和 METRICS 各自持有一个实例。

### 5.2 功能

- 级别不够的记录不入队。
- 级别足够的记录克隆后非阻塞入队。
- 后台协程调用底层 handler 写出。
- 关闭时排空队列，并限制等待时间。

### 5.3 性能

- 通道容量 4096。
- `Handle` 在通道已满时立即返回，不等待写出。
- 底层 IO 只发生在后台协程，以及关闭时的排空阶段。

### 5.4 输入项

| 输入 | 说明 |
| --- | --- |
| 底层 handler | 最终写出目标。未指定时使用 `slog.Default()` 的 handler |
| 日志记录 | `slog.Record` |

### 5.5 输出项

| 输出 | 说明 |
| --- | --- |
| 写出结果 | 由底层 handler 完成 |
| 丢弃计数 | 通道满或排空超时 |

### 5.6 算法

```text
Enabled
    转给底层 handler

Handle
    若级别不够：返回
    克隆记录
    若通道可发送：入队
    否则：丢弃计数加一
    返回 nil

后台协程
    取出记录并调用底层 Handle

Close
    关闭通道
    等待后台协程，最长 2 秒
    超时未写出的记录计入丢弃数
```

`WithAttrs` 和 `WithGroup` 作用在底层 handler 上，再包回新的异步 handler。属性在入队前写入记录。

### 5.7 流程逻辑

ENGINE 的 `Stop` 和 METRICS 的上下文结束，都先停止自己的业务循环，再调用 `Close`。排空阶段允许 IO，因为事件循环已经退出。

两个程序的丢弃数互不写入对方。快照中的日志丢弃数只来自 ENGINE 的实例。

### 5.8 接口

```go
func New(sink slog.Handler) *Logger
func (l *Logger) Handler() slog.Handler
func (l *Logger) Dropped() uint64
func (l *Logger) Close() 
```

`Close` 内部使用 2 秒时限，不接受外部超时参数。

### 5.9 存储分配

一条带缓冲通道、一个丢弃计数、一个后台协程。记录在入队前克隆，避免调用方复用记录内存。

### 5.10 注释设计

说明 `Handle` 不返回队列已满错误，避免调用方在事件循环里处理 IO 失败。

### 5.11 限制条件

- 底层 handler 的 `Enabled` 不能执行 IO。
- `Close` 只能调用一次。
- 队列满时丢弃新记录，不丢弃已入队记录。

### 5.12 测试计划

| 编号 | 内容 |
| --- | --- |
| A1 | 通道有空间时，`Handle` 在底层写出之前返回 |
| A2 | 通道满时，`Handle` 立即返回且丢弃计数增加 |
| A3 | `Close` 后，已入队记录出现在底层 handler 中 |
| A4 | 级别不够的记录不入队 |

### 5.13 尚未解决的问题

无。

## 6 METRICS 设计说明

### 6.1 程序描述

METRICS 读取 ENGINE 快照，提供健康检查、JSON 状态和 Prometheus 文本。它在独立 HTTP 协程上运行。

### 6.2 功能

- 按地址监听。
- 上下文结束时关闭 HTTP 服务和自己的异步日志。
- 生成第 5.2 节定义的两种表示。

### 6.3 性能

编码期间不持有引擎锁。快照在 `Snapshot()` 返回前已经复制慢事件切片。

### 6.4 输入项

| 输入 | 说明 |
| --- | --- |
| 上下文 | 结束时关闭服务 |
| 监听地址 | `net/http` 地址 |
| 快照来源 | 必须实现 `Snapshot() engine.Snapshot` |
| 日志目标 | 可为 nil |

### 6.5 输出项

| 输出 | 说明 |
| --- | --- |
| HTTP 响应 | `/healthz`、`/status`、`/metrics` |
| 返回错误 | 监听失败时由 `Listen` 返回 |
| 日志 | 监听开始和停止 |

### 6.6 算法

Prometheus 文本由固定指标名拼接，不使用事件名称或事件标识作为标签。JSON 按第 5.2 节的字段名编码。

### 6.7 流程逻辑

```text
Listen
    创建本服务专用的 ASYNCLOG
    在新协程上 Serve
    若监听失败：关闭日志并返回错误
    等待上下文结束
    Shutdown HTTP
    关闭 ASYNCLOG
    返回 nil
```

### 6.8 接口

```go
func Listen(ctx context.Context, addr string, src interface{ Snapshot() engine.Snapshot }, logger *slog.Logger) error
```

### 6.9 存储分配

无业务存储。响应从一次快照临时生成。

### 6.10 注释设计

godoc 说明 `/healthz` 表示 HTTP 服务仍在监听，不表示仿真仍在运行。

### 6.11 限制条件

- 不修改引擎状态。
- 不提供事件名称维度的 Prometheus 序列。
- 引擎停止后 `/healthz` 仍返回 200，直到指标服务自身退出。

### 6.12 测试计划

使用 `httptest`。

| 编号 | 内容 |
| --- | --- |
| M1 | `/healthz` 返回 200 和 `ok` |
| M2 | `/status` 包含慢事件的名称、仿真时间和耗时 |
| M3 | `/metrics` 的 `des_slow_events_total` 与快照一致，且不含事件名称标签 |
| M4 | 上下文取消后 `Listen` 返回 |

### 6.13 尚未解决的问题

无。

### 7.11 限制条件

## 8 共用数据与接口

本章集中列出跨程序使用的快照、HTTP 和日志，避免在各程序中重复定义。

### 8.1 快照

`Snapshot()` 在引擎锁内复制计数、滞后、队列长度和慢事件切片。

```go
type Snapshot struct {
    State           string
    Now             Time
    Step            int64
    Lag             time.Duration
    EventsPending   int
    StepPending     int
    EventsScheduled uint64
    EventsProcessed uint64
    EventsCancelled uint64
    EventsRejected  uint64
    HandlerErrors   uint64
    CatchupSteps    uint64
    SlowTotal       uint64
    LogDropped      uint64
    Uptime          time.Duration
    EventRate       float64
    SlowEvents      []SlowEvent
}
```

- `EventsPending`：未来桶事件数与 `StepPending` 长度之和。
- `EventRate`：`EventsProcessed / Uptime`。运行时间为 0 时速率为 0。
- `Step`：有正在执行的毫秒时取 `executing`，否则取 `watermark`。
- `SlowEvents`：按发生顺序排列，最新一条在最后，最多 128 条。

### 8.2 HTTP

| 路径 | 响应 |
| --- | --- |
| `GET /healthz` | `200`，正文 `ok` |
| `GET /status` | `application/json` |
| `GET /metrics` | `text/plain; version=0.0.4` |

`/status` 使用蛇形字段。仿真时间用整数毫秒，时间间隔用秒的浮点数。
